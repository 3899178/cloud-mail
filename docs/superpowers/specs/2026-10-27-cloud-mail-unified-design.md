## 架构与安全

Cloudflare 保留原站和原数据；AWS 新增 Node.js 24 同步服务、SQLite WAL、独立附件目录和隔离的 Proton Go 适配器。Worker 用短时签名用户断言访问受保护的同步服务，不能信任客户端 userId。租户数据、外部凭据和设备权限必须隔离。

新增接口：/api/external/accounts（绑定/授权/重新登录/暂停/解绑/状态）、/api/unified/messages（统一列表、正文、附件、已读、删除、发送/回复/转发）、/api/devices（限权设备绑定和撤销）。原 API 保持兼容。消息采用带来源的不透明引用，统一列表使用收信时间加稳定引用的游标，不能因数字 ID 相同操作错信。

外部凭据在 AWS 加密保存；主密钥、服务密钥由部署机私有配置管理，不进入仓库、HTML、浏览器 localStorage、普通日志、导出或 APK。网页登录迁移到 Secure/HttpOnly/SameSite Cookie，保留旧 Bearer API；既有浏览器凭据一次性交换成功后清理，写操作实施同源和 CSRF 校验。

Gmail/Outlook 使用官方 OAuth2；Gmail 可使用账户允许的应用专用密码。QQ、网易系、iCloud、学校及其他邮箱使用允许的 IMAP/SMTP 和授权码/专用密码。不得借用第三方 client ID，也不得伪造服务商权限。

Proton 社区候选固定为 Codeberg emersion/hydroxide@02b3b6c8aff726d2404b6ed5f6ba1b7937e1f30e。其 IMAP 会重建 UID 映射且 UIDVALIDITY 固定，不能直接将桥接 UID 当增量游标。独立 Go helper 复用其客户端，使用 Proton 稳定消息 ID 和事件检查点，通过本机 Unix socket 与 Node 通信；保留 MIT 署名。免费及付费账号分别实测，未验证不能标可用，不能默默删掉 Proton 目标或用官网跳转冒充完成。

## 资源与部署

2026-10-27 已只读核对 AWS：x86_64、2 逻辑 CPU、909MiB 总内存、约 424MiB available、2GiB swap、29GiB 空闲磁盘；Docker 可用，cliproxy-caddy 占用 80/443，存在其他业务容器。不得关停或重写其他应用。

远程仅用已有 ssh AWS，保持严格主机密钥校验；SSH 私钥不得读取、复制或上传 CI。实际生产备份、权限及数据差异是生产部署的前置门禁；缺少授权时可进行隔离本地开发，但不能跳过部署门禁。
